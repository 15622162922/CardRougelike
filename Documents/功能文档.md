# CardRougelike 卡牌游戏项目功能文档

## 项目概述

**项目名称**: CardRougelike  
**项目类型**: Unity 3D 卡牌肉鸽游戏  
**引擎版本**: Unity  
**主要技术栈**: C#, HybridCLR(热更新), YooAsset(资源管理), NodeGraphProcessor(事件流程图)

---

## 一、核心架构

### 1.1 模块化架构

项目采用模块化管理，主要包含以下核心模块：

| 模块 | 说明 |
|------|------|
| CharacterModule | 角色模块 - 玩家、NPC、怪物的创建与管理 |
| MapModule | 地图模块 - 地图加载与Tilemap生成 |
| StoryModule | 故事/对话模块 - 剧情系统 |

### 1.2 管理器系统

项目实现了一套管理器基类系统，所有管理器继承自 `BaseManager`：

```
BaseManager<T>
├── GameManager        - 游戏主管理器，协调各模块
├── ModuleManager      - 模块管理器，注册/注销游戏模块
├── ConfigManager      - 配置管理器，加载游戏数据配置
├── EventManager       - 事件管理器，系统级事件分发
├── MsgManager         - 消息管理器，组件间通信
├── LoadManager        - 资源加载管理器
│   ├── AssetBundleLoader    - AssetBundle加载
│   ├── AssetDatabaseLoader  - Editor模式加载
│   └── ResourceManager      - 通用资源管理
├── MapManager         - 地图管理器
├── UIManager          - UI管理器
│   ├── BaseUILayer    - 基础UI层级
│   ├── UIPageLayer    - 页面层级
│   ├── UIPopupLayer   - 弹窗层级
│   └── UITipsLayer   - 提示信息层级
├── UpdateManager      - 更新管理器
└── ObjectPoolManager  - 对象池管理器
```

## 二、角色系统

### 2.1 角色类型

项目定义了三种角色类型（RoleConst.RoleType）：

- **Player** - 玩家角色
- **Monster** - 怪物/敌人
- **Npc** - 非玩家角色

### 2.2 角色组件系统

角色系统采用组件化设计，支持动态添加/移除组件：

| 组件 | 功能 |
|------|------|
| RoleMoveComponent | 移动控制 |
| RoleAttackComponent | 攻击/战斗 |
| RoleAttrComponent | 属性管理（生命值、攻击力等） |

### 2.3 命令与事件系统

- **Command系统**: 支持外部向角色发送指令（RoleCommand）
- **Event系统**: 支持组件间事件通信（RegisterRoleEvent/DispatchRoleEvent）

## 三、战斗系统

### 3.1 职业系统

角色分为多种职业，不同职业拥有不同的属性和卡组：

| 职业 | 说明 | 特点 |
|------|------|------|
| Warrior | 战士 | 近战物理输出，高生命 |
| Mage | 法师 | 远程魔法输出，高攻击 |
| Rogue | 盗贼 | 爆发物理输出，高攻速 |

**职业属性差异**：
- 基础生命值、攻击力、攻击范围
- 攻击间隔、移动速度
- 能量上限、能量回复率

### 3.2 普通攻击系统

- **触发机制**：自动触发，检测范围内敌人
- **攻击形态**：全方位扫击
- **冷却时间**：受职业AttackInterval控制

### 3.3 卡牌系统

#### 单位时间机制
- 每隔3秒回复1点能量
- 每隔3秒从卡组抽取1张卡牌到手牌

#### 卡牌类型
| 类型 | 说明 |
|------|------|
| Attack | 攻击牌 |
| Defense | 防御牌 |
| Skill | 技能牌 |
| Power | 能力牌 |

#### 目标类型
| 类型 | 说明 |
|------|------|
| None | 无目标（直接释放） |
| Enemy | 敌方目标（拖拽选择） |
| Ally | 友方目标（拖拽选择） |
| Self | 自身目标 |
| Position | 位置目标 |

#### 卡牌效果
- Damage、Heal、DrawCard、GainEnergy
- ApplyBuff、RemoveBuff、Summon、Dash、AreaDamage

### 3.4 Buff系统

- **Buff收集器**：集成在RoleAttrComponent中
- **Buff标签**：ATK、DEF、SPD、CRIT、LIFE、ENERGY等
- **加成计算**：支持多标签叠加和效果加成

### 3.5 组件列表
| 组件 | 说明 |
|------|------|
| RoleClassComponent | 职业组件 |
| RoleCardComponent | 卡牌组件 |
| RoleEnergyComponent | 能量组件 |

## 四、游戏流程系统

### 4.1 Game类

游戏主控制器，管理整场游戏生命周期：

- **单例模式**：通过`Game.NewGame()`启动新游戏
- **状态管理**：None → Loading → Playing ↔ Paused → Summary

### 4.2 游戏状态

| 状态 | 说明 |
|------|------|
| None | 初始状态 |
| Loading | 资源加载中 |
| Playing | 游戏进行中 |
| Paused | 游戏暂停 |
| Summary | 结算阶段 |

### 4.3 启动流程
1. 生成随机种子
2. 创建数据收集器
3. 加载地图
4. 创建玩家角色
5. 初始化卡牌系统
6. 创建怪物管理器
7. 状态切换为Playing

### 4.4 结束条件
| 条件 | 说明 |
|------|------|
| PlayerDied | 玩家死亡 |
| BossDefeated | 击败最终Boss |
| Quit | 主动退出 |

### 4.5 结算流程
1. 生成结算数据（GameSummary）
2. 同步数据到全局收集器
3. 成就检测
4. 解锁检测（卡牌、装饰物）
5. 升级经验计算

### 4.6 数据收集器

记录本局游戏所有统计数据：

| 类别 | 数据 |
|------|------|
| 战斗统计 | TotalDamage、CriticalHits、HighestSingleDamage |
| 卡牌统计 | CardsPlayed、EnergySpent、CardsDrawn |
| 敌人统计 | EnemiesKilled、BossEnemiesKilled |
| 房间统计 | RoomsEntered、RoomsCleared、ShopsVisited |

## 五、地图系统

### 5.1 地图配置

地图数据通过Excel配置表管理，存储于 `Excel/` 目录：

- `MapDataConfig.xlsx` - 地图配置表
- `TileDataConfig.xlsx` - 瓦片数据配置表

### 5.2 地图生成

- 基于Tilemap的2D网格地图
- 支持随机种子生成（RandomChunkLayout算法）
- 支持地图分块：基础地图、增益区域、起点、终点

### 5.3 房间系统

地图系统采用模块化的房间设计，支持程序化生成与人工编辑相结合：

#### 房间类型
| 类型 | 说明 |
|------|------|
| StartRoom | 起始房间 |
| NormalRoom | 普通战斗房间 |
| EliteRoom | 精英战斗房间 |
| RestRoom | 休息/事件房间 |
| ShopRoom | 商店房间 |
| TreasureRoom | 宝箱房间 |
| BossRoom | Boss房间 |

#### 核心组件
- `RoomTemplate` - 房间模板（ScriptableObject）
- `RoomGraphGenerator` - 房间图生成器（分支路径算法）
- `RoomPlacer` - 房间放置器（位置计算）
- `ExitEditor` - 出口编辑器（房间连接）

#### 房间编辑器
- `RoomEditorWindow` - 主编辑器窗口
- `TilePainter` - 瓦片绘制器
- `RoomPreviewWindow` - 房间预览窗口
- `MapTestWindow` - 地图生成测试窗口

#### 生成流程
```
1. 初始化随机种子
2. 创建起点房间和终点Boss房间
3. 规划多条主路径（连接起点和终点）
4. 在主路径上添加分支路径
5. 建立分支之间的横向连接，使不同路径连通
6. 在路径上插入特殊房间
7. 验证路径连通性
8. 计算房间物理位置
9. 生成走廊连接
```

支持两种资源加载模式：
